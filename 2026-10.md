# Учёт задач Claude Code — октябрь 2026

### 2026-10-01 · GOODTLAB-4395 · Ошибка с серьёзными последствиями

**Задача.** Тестировщик обнаружила, что выдача и отзыв прав при совместном доступе работают по-разному
для объектов IDP, IQE и проектов, а окно настройки доступа в каталоге открывается за пределами экрана.

**Что сделано.** Пользователь может выдать другим только те права, которые есть у него самого; без права
«управление доступом» форма открывается только для просмотра; делегат не может отозвать доступ у себя
и в проектах; убран переключатель видимости, который выглядел как настройка доступа, но ни на что не
влиял; ошибки удаления в IDP стали понятными; журнал аудита фиксирует фактический результат действия.
Настройка доступа открывается в боковой панели объекта. Затронуто 26 файлов.

**Почему потребовался Claude.** Права складываются из трёх источников — внешней системы управления
доступом, локального владельца и режима суперпользователя — с наследованием от папок и групп из токена.
Проверка «нельзя выдать больше своих прав» должна вычислять права ровно так же, как все существующие
проверки доступа, иначе получается либо обход ограничений, либо ложные отказы. Для этого нужно было
держать вместе около 720 тыс. токенов связанного кода — больше окна любой локальной модели и любой
модели lanit, работающей в режиме рассуждений (единственная lanit-модель с окном 1 млн — без рассуждений). Цена ошибки — эскалация прав. Основная работа — Claude Opus 5.5, интерфейс и аудит —
агенты на Claude Sonnet 5.5.

**Ближайшие модели из списка гранта и почему они не подошли.**
- *GLM-5.3-Flash и DKS-Leo (lanit)* — самые сильные локальные модели с режимом рассуждений, окно
  524 тыс. токенов. Объективно не справились бы: связанный код (~720 тыс. токенов) в их окно не помещается.
- *DeepSeek-V4.1-Flash (lanit)* — единственная локальная модель с окном 1 млн, код поместился бы. Но она
  работает без режима рассуждений, а задача требовала доказать, что новая проверка вычисляет права
  точно так же, как десяток существующих — без пошагового рассуждения такая модель справилась бы хуже,
  с риском оставить обход ограничений.

### 2026-10-01 · GOODTLAB-4407 · Поиск неочевидных причин сложных ошибок

**Задача.** SQL-переменные пользователя (построчная фильтрация по данным из профиля) давали ошибку
«query failed» при проверке формул и при сохранении SQL-запроса, а поведение при материализации было
неясно тестировщику.

**Что сделано.** Найдены две разные причины одной и той же ошибки: проверка формул шла отдельным путём
без подстановки переменных, а проверка SQL не передавала движку бакет датасета. Обнаружена и закрыта
утечка данных, которая ошибкой не проявлялась вовсе: материализация View с построчным фильтром
сохраняла строки того, кто её запустил, и показывала их всем. Подстановка переменных выровнена по всем
путям чтения данных, включая AI-чат и MCP; подготовлены бизнес-алгоритм и критерии приёмки. Затронуто
19 файлов.

**Почему потребовался Claude.** Движок на любую ошибку отвечает одним и тем же «query failed», поэтому
причину нельзя найти по сообщению — пришлось проследить все ~15 мест, где формируется SQL, в коде объёмом
около 500 тыс. токенов — больше окна любой локальной модели из списка гранта. Утечку не показывает ни один тест и ни одна ошибка: её можно найти только
рассуждением о том, как материализация сочетается с персональным фильтром. Основная работа — Claude
Opus 5.5, интерфейс, AI-чат и MCP — агенты на Claude Sonnet 5.5.

**Ближайшие модели из списка гранта и почему они не подошли.**
- *GLM-5.3-Flash и DKS-Leo (lanit)* — окно 524 тыс. токенов, режим рассуждений есть. Код (~500 тыс.
  токенов) помещается впритык: на системные инструкции, результаты поиска по коду и прогонов тестов
  остаётся около 24 тыс. токенов, а в этой задаче одни только результаты инструментов были больше. На
  практике окно переполнилось бы до завершения разбора.
- *DeepSeek-V4.1-Flash (lanit)* — окно 1 млн, код поместился бы, но без режима рассуждений. Ошибки
  она, вероятно, нашла бы перебором мест формирования SQL, а утечку — нет: она не проявляется ни
  ошибкой, ни тестом и находится только рассуждением. Справилась бы хуже, оставив уязвимость.

### 2026-10-02 · Без тикета (аудит доступа IQE, остаток GOODTLAB-4594) · Ошибка с серьёзными последствиями

**Задача.** Тестировщик заметила, что датасет типа «виртуальный запрос» не ограничивается правами
доступа. Нужно было проверить, как права работают у всех производных датасетов локального движка
(View, объединения, SQL-слой, материализации) и у флага «доступен всем».

**Что сделано.** Найдена и закрыта утечка: любой вошедший пользователь мог прочитать любой датасет
любой команды, указав в SQL путь к его файлу. Права на источники теперь проверяются рекурсивно при
каждом чтении и при сохранении, SQL пользователя не может сослаться на чужой файл. Ссылка на публичный
проект открывает только данные этого проекта. «Доступен всем» больше не выходит за пределы бакета
по прямому id — эту часть GOODTLAB-4594 оставила открытой. Чтение списка перестало удалять чужие
записи, а выдача доступа через проект — раздавать больше прав, чем есть у выдающего. Затронуто
23 файла на TypeScript, разобран движок на Rust.

**Почему потребовался Claude.** Утечку не показывал ни один тест и ни одна ошибка: её нашли
рассуждением о том, как DuckDB открывает файлы из текста запроса (функции чтения, имена файлов в
кавычках, экранированные строки), и о том, что сервер это никак не проверяет. Для этого нужно было
держать вместе маршруты, проверку прав, разбор SQL на сервере и движок на Rust — около 518 тыс.
токенов связанного кода. Это больше окна любой модели гранта с режимом рассуждений. Цена ошибки —
чтение чужих данных между командами. Основная работа — Claude Opus 5.5, интерфейс — агенты на
Claude Sonnet 5.5.

**Ближайшие модели из списка гранта и почему они не подошли.**
- *GLM-5.3-Flash и DKS-Leo (lanit)* — окно 524 тыс. токенов, режим рассуждений есть. Объективно не
  справились бы: связанный код (~518 тыс. токенов) занимает окно почти целиком, и на системные
  инструкции, результаты поиска и прогоны тестов места не остаётся.
- *DeepSeek-V4.1-Flash (lanit)* — окно 1 млн, код поместился бы, но без режима рассуждений.
  Справилась бы хуже: дыра не проявляется ни ошибкой, ни тестом, её находят только рассуждением о
  поведении движка. Без него модель, скорее всего, ограничилась бы исправлением исходного случая,
  а обход через путь к файлу остался бы открытым.

### 2026-10-02 · GOODTLAB-4594 (остаток: «Доступен всем») · Ошибка с серьёзными последствиями

**Задача.** У датасетов и папок локального хранилища был один флаг «Доступен всем», и он означал
сразу две вещи: «видят все сотрудники с доступом к хранилищу» и «видят анонимные зрители публичных
проектов, без входа». Открывая датасет коллегам, пользователь заодно открывал его наружу. Флаг на
папке так же открывал анонимам все датасеты в ней, а настройка «видимость новых загрузок по
умолчанию» могла сразу выставлять наружу всё загружаемое.

**Что сделано.** Вместо флага — три уровня общего доступа: «Ограниченный» (владелец и выданные
права), «Все в бакете» (вошедшие пользователи с доступом к хранилищу), «Доступен всем» (плюс
анонимные зрители публичных проектов). Анонимам открывается только датасет, у которого этот уровень
выставлен на нём самом: папка наружу не открывает никогда, новые загрузки и диаграммы ИИ-агента
наружу по умолчанию не выходят. Старые значения прочитаны без миграции данных: прежнее «доступно
всем» у папки стало «Все в бакете». Один и тот же выбор уровня показан для датасетов и папок
локального хранилища и для датасетов IDP. При понижении уровня платформа называет публичные проекты,
которые потеряют анонимных зрителей. Затронуто 28 файлов.

**Почему потребовался Claude.** Уровень доступа читается и выставляется во многих местах: проверка
прав, маршруты хранилища, загрузка файлов и Google Sheets, внешние источники, инструменты ИИ-агента,
схема БД и все экраны, где его видно. Изменить смысл флага нужно было во всех местах сразу:
пропущенное место, которое по-прежнему понимает «доступен всем» как «и анонимам», оставляет данные
открытыми наружу. Ни тест, ни сообщение об ошибке такое место не показывают. Объём затронутого кода
по методике журнала — около 611 тыс. токенов (из них серверная часть — около 390 тыс.). Это больше
окна любой модели гранта с режимом рассуждений. Цена ошибки — данные команды, видимые без входа по
ссылке на публичный проект. Основная работа — Claude Opus 5.5.

**Ближайшие модели из списка гранта и почему они не подошли.**
- *GLM-5.3-Flash и DKS-Leo (lanit)* — окно 524 тыс. токенов, режим рассуждений есть. Объективно не
  справились бы целиком: затронутый код (~611 тыс. токенов) в окно не помещается. Серверная часть
  (~390 тыс.) поместилась бы, но тогда сервер и интерфейс пришлось бы менять раздельно, без проверки,
  что каждый экран выставляет только те уровни, которые сервер понимает так же.
- *DeepSeek-V4.1-Flash (lanit)* — окно 1 млн, код поместился бы, но без режима рассуждений.
  Справилась бы хуже: задача — найти все места, где «доступен всем» неявно включает анонимов (папка,
  настройка по умолчанию, агент), а их не видно ни по ошибкам, ни по тестам; без пошагового
  рассуждения велик риск оставить одно из них.
