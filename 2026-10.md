# Учёт задач Claude Code — октябрь 2026

### 2026-10-01 · GOODTLAB-4395 · Ошибка с серьёзными последствиями

**Задача.** Тестировщик обнаружила, что выдача и отзыв прав при совместном доступе работают по-разному
для объектов IDP, IQE и проектов, а окно настройки доступа в каталоге открывается за пределами экрана.

**Что сделано.** Пользователь может выдать другим только те права, которые есть у него самого; без права
«управление доступом» форма открывается только для просмотра; делегат не может отозвать доступ у себя
и в проектах; убран переключатель видимости, который выглядел как настройка доступа, но ни на что не
влиял; ошибки удаления в IDP стали понятными; журнал аудита фиксирует фактический результат действия.
Настройка доступа открывается в боковой панели объекта. Затронуто 26 файлов.

**Почему потребовался Claude.** Права складываются из трёх источников — внешней системы управления
доступом, локального владельца и режима суперпользователя — с наследованием от папок и групп из токена.
Проверка «нельзя выдать больше своих прав» должна вычислять права ровно так же, как все существующие
проверки доступа, иначе получается либо обход ограничений, либо ложные отказы. Для этого нужно было
держать вместе около 720 тыс. токенов связанного кода — больше окна любой локальной модели и любой
модели lanit, работающей в режиме рассуждений (единственная lanit-модель с окном 1 млн — без рассуждений). Цена ошибки — эскалация прав. Основная работа — Claude Opus 5.5, интерфейс и аудит —
агенты на Claude Sonnet 5.5.

### 2026-10-01 · GOODTLAB-4407 · Поиск неочевидных причин сложных ошибок

**Задача.** SQL-переменные пользователя (построчная фильтрация по данным из профиля) давали ошибку
«query failed» при проверке формул и при сохранении SQL-запроса, а поведение при материализации было
неясно тестировщику.

**Что сделано.** Найдены две разные причины одной и той же ошибки: проверка формул шла отдельным путём
без подстановки переменных, а проверка SQL не передавала движку бакет датасета. Обнаружена и закрыта
утечка данных, которая ошибкой не проявлялась вовсе: материализация View с построчным фильтром
сохраняла строки того, кто её запустил, и показывала их всем. Подстановка переменных выровнена по всем
путям чтения данных, включая AI-чат и MCP; подготовлены бизнес-алгоритм и критерии приёмки. Затронуто
19 файлов.

**Почему потребовался Claude.** Движок на любую ошибку отвечает одним и тем же «query failed», поэтому
причину нельзя найти по сообщению — пришлось проследить все ~15 мест, где формируется SQL, в коде объёмом
около 500 тыс. токенов — больше окна любой локальной модели из списка гранта. Утечку не показывает ни один тест и ни одна ошибка: её можно найти только
рассуждением о том, как материализация сочетается с персональным фильтром. Основная работа — Claude
Opus 5.5, интерфейс, AI-чат и MCP — агенты на Claude Sonnet 5.5.
