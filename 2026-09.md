# Учёт задач Claude Code — сентябрь 2026

### 2026-09-30 · GOODTLAB-4337 · Архитектура нескольких модулей

**Задача.** Материализация (копирование датасета из IDP в локальный движок IQE) выполнялась внутри
одного HTTP-запроса: на больших датасетах обрывалась по таймауту, пользователь не видел прогресса и не
мог её отменить.

**Что сделано.** Материализация вынесена в фоновые задачи: прогресс по этапам, отмена между страницами
загрузки, одна активная задача на датасет, корректное завершение при перезапуске сервера. Затронуто
10 файлов на стороне сервера и интерфейса.

**Почему потребовался Claude.** Корректность определяется согласованием четырёх слоёв — постраничной
загрузки из IDP, записи данных в IQE, хранения состояния задачи в PostgreSQL и опроса прогресса в
интерфейсе: отмена посреди страницы, перезапуск посреди загрузки, повторный запуск того же датасета.
Связанный код — около 350 тыс. токенов, из них только файл маршрутов IQE — 640 КБ; это больше окна
контекста всех локальных моделей гранта, а модели с бо́льшим окном работают либо без режима
рассуждений, либо с ответом до 10 тыс. токенов.

### 2026-09-30 · GOODTLAB-4396 · Ошибка с серьёзными последствиями

**Задача.** Автообновление материализаций по расписанию работало нестабильно: часть запусков не
выполнялась, на части датасетов появлялась ошибка доступа владельца. Воспроизвести по шагам не удавалось.

**Что сделано.** Найдена причина: refresh-токен Keycloak ротируется при каждом обновлении, а браузер,
ручной запуск и планировщик использовали один и тот же токен и взаимно его инвалидировали; кроме того,
токен сохранялся за тем, кто нажал кнопку, а не за владельцем датасета. Введён отдельный offline-токен
владельца (одноразовый state, сверка пользователя, хранится только refresh-токен), запуски по
расписанию перенесены в фоновые задачи без наложений, ошибки доступа стали понятными. Затронуто 21 файл.

**Почему потребовался Claude.** Причина не видна ни в одном файле по отдельности: она проявляется
только при одновременном разборе потока OAuth, хранилища токенов, планировщика и интерфейса — около
370 тыс. токенов связанного кода. Ошибка в этом месте означает фоновый доступ к данным от имени другого
пользователя, поэтому решение требовало пошаговой проверки сценариев атаки на обратный вызов OAuth.
Основная работа — Claude Opus 5.5, вспомогательные агенты — Claude Sonnet 5.5.
